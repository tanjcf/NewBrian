# 游戏制作场景：对话驱动右侧 Tools 页面验收

## 执行规则

启动可见 BRAIN 后，只用鼠标和键盘完成页面操作：切换「游戏制作」、选择项目、点击右侧功能、聚焦对话框并输入下面的提示词。不得用 IPC、`window.newbrain` 或直接写文件替代用户动作。每个案例都要记录对话原文、模型工具名与参数、右侧 Tools 变化、工程文件变化和页面最终状态。

## 前置

1. 页面新建一个空白游戏项目并选中它。
2. 进入「游戏制作」，确认右侧显示「关卡 / 项目与文件 / 游戏策划 / 角色与世界观 / 战斗设计 / 资产与测试」。
3. 新建独立对话，避免上一个案例的上下文混入下一个案例。

## 案例 1：关卡与项目资源

对话输入：

> 在当前游戏项目中创建一个名为“青石谷入口”的新关卡，保存到真实项目；然后读取当前项目的关卡和 Content 资源，返回实际写入路径和数量。不要编造关卡、资产或试玩数据。

页面验收：右侧关卡列表出现新关卡；项目与文件显示真实检查结果；对话中出现实际工具调用和结果；重载页面后关卡仍存在。

## 案例 2：角色与世界观

对话输入：

> 为当前游戏项目建立“青石谷入口”的世界观设定：主角、敌对势力、区域规则和本关目标。请把内容保存到当前项目的角色与世界观资料，并在右侧对应面板显示已保存内容。

页面验收：右侧「角色与世界观」出现保存后的真实内容；不得只在聊天里生成文本；刷新后内容仍可读取。

## 案例 3：战斗设计与敌人

对话输入：

> 在“青石谷入口”关卡添加一个巡逻敌人，名称“山魈哨兵”，设置出生点、巡逻行为和仇恨范围；保存关卡并返回实际工程写入结果。没有真实 AI/资产管线时明确报告未接入，不要伪造成功。

页面验收：关卡 Outliner 或保存状态出现真实结果；若能力未接入，右侧必须显示明确的未接入状态，不得出现假 AI 资产。

## 案例 4：资产与测试

对话输入：

> 检查当前游戏项目的资产和测试能力，列出真实 Content、Levels、AI 资产和可运行预览；对缺失的资产或未接入的测试能力逐项标记，不要创建演示数据。

页面验收：右侧「资产与测试」显示真实检查结果；空工程显示空状态而不是预置资源；预览入口只有在真实启动脚本存在时才可用。

## 案例 5：对话到 Tools 的连续闭环

对话输入：

> 先读取当前工程状态，再创建“青石谷入口”关卡，保存后添加山魈哨兵，最后检查预览入口。每一步都必须调用对应的右侧游戏 Tools，并在完成后说明工具结果、写入文件和下一步状态。

页面验收：同一对话中能看到有顺序的工具调用；每次写操作按页面批准流程执行；右侧关卡、Content、Outliner、保存状态和预览状态与工具结果一致；重启后重新打开项目核对无重复或丢失。

## 结果判定

- `PASS`：对话输入、可见工具调用、右侧变化、持久化结果和重启核验全部有证据。
- `PARTIAL`：只证明 IPC/服务或只生成聊天文本，未证明页面 Tools 联动。
- `FAIL`：工具未调用、右侧仍是模拟数据、写入结果与页面不一致或上下文串入其他对话。
