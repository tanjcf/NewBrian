# BRAIN 多工作台产品架构与实施路线

> 配套执行手册：[implementation-playbook.md](./implementation-playbook.md)  
> 桌面边界与分层：[../architecture/brain-product-architecture.md](../architecture/brain-product-architecture.md)、[../architecture/repository-layout.md](../architecture/repository-layout.md)

## 1. 文档目标

本方案定义 BRAIN 从对话助手演进为多工作台智能生产平台的产品结构、交互规则、技术边界、Rust 演进路径和阶段性交付计划。

第一阶段必须提供七个可进入、可创建项目、可使用文件和对话的工作台：

1. 量化交易
2. 游戏制作
3. 视频制作
4. 音乐创作
5. 数据与决策
6. 软件与自动化
7. 文档创作

专业子功能允许逐步建设，但不能用空白页代替工作台。尚未完成专业编辑器的工作台至少必须支持项目、对话、文件、产物、任务、BRAIN 协作和明确的能力状态。

> 实施基线（2026-08-19）：七工作台、本地项目/对话/草稿、左上切换器、右侧文件/产物/任务基础面板、Windows 用户私有模型密钥保险库和本地数据库损坏恢复已经进入 BRAIN `main` 分支。量化、文档、游戏、视频、音乐等专业编辑器以及 Rust Core 仍按后续阶段推进；不得将基础骨架的完成描述成全部专业能力完成。

## 2. 已确认的产品决策

### 2.1 三个核心概念

- 工作台决定使用哪些专业工具。
- 项目承载一个持续目标以及文件、对话、产物、任务和 Skill。
- 对话是项目中完成目标的过程记录，不是数据归属的最高层级。

归属关系：

```text
工作台
└─ 项目
   ├─ 文件
   ├─ 对话
   ├─ 产物
   ├─ 任务
   ├─ Skill
   └─ 工作台状态
```

### 2.2 工作台切换位置

- 工作台切换器固定在左侧最上方，采用与 Codex 全局上下文切换相同的层级。
- 点击后打开七个工作台的卡片式选择面板。
- 左侧项目主目录沿用 Claude Code / NewBrain 本地文件夹目录（`WorkspaceCatalogItem.path` + 线程），七场景通过 `brainWorkspaceKey` 过滤；无键历史默认归入文档创作。`brain_project` 只作场景工具元数据桥接，不替代左侧主目录。
- 切换工作台后，左侧项目/聊天列表和右侧专业工具同步更新。
- 当前对话不能因为误触工作台而立即丢失；未发送输入必须保留。
- “最近”区域提供跨工作台返回入口。

### 2.3 图标与视觉规则

- 复用原 BRAIN 的 16px 单色线性图标语言。
- 禁止在同一导航中混用 Emoji、字符图标和多套 SVG 风格。
- 下拉、全屏、侧栏、文件、产物、任务和专业模块均使用统一 SVG 图标。
- 工作台颜色只用于选中状态和小面积识别，不改变原有 BRAIN 主界面结构。

### 2.4 全局能力与专业能力

全局能力不属于任何单一工作台：

- 文件
- 产物
- 任务
- 通知
- 搜索
- Skill
- 插件
- 自动化

右侧面板第一层固定提供文件、产物和任务，第二层根据当前工作台显示专业功能。

## 4. BRAIN 智能路由

用户不需要先选择工作台。BRAIN 根据任务和当前项目自动建议或进入工作台：

- 股票、公告、回测、模拟买卖进入量化交易。
- 游戏策划、关卡、角色和战斗进入游戏制作。
- 脚本、分镜、剪辑和字幕进入视频制作。
- 歌词、旋律、配乐和混音进入音乐创作。
- 表格、统计、图表和经营分析进入数据与决策。
- 代码、终端、测试、部署和 Agent 进入软件与自动化。
- 文章、报告、PPT、合同和审校进入文档创作。

自动路由必须遵循：

1. 优先继承当前项目的主工作台。
2. 置信度不足时只建议，不强制切换。
3. 需要跨工作台时启用辅助工作台，不复制项目和文件。
4. 自动切换必须记录原因，并允许撤销。
5. 管理员统一配置模型、搜索、专业工具和降级链，普通用户零配置。

## 5. 联网搜索与时效信息

- 涉及最新消息、公告、政策、新闻、价格和时效信息时自动搜索。
- 普通知识、计算、改写和普通代码问题默认不联网。
- 证券新闻和可用的免费行情源优先，付费 Web Search 作为补充和兜底。
- 搜索回答必须附来源链接、数据源和搜索时间。
- 搜索失败时明确提示，不允许模型编造最新信息。
- 搜索网关保持独立节点，通过 WireGuard 内网访问，不向公网暴露业务端口。

### 5.1 密钥与调用边界

- BRAIN 同时支持“公司托管模型”和“用户私有模型/BYOK”，两者必须使用不同的密钥链路和信任域。
- 对公司密钥，BRAIN 桌面端必须做到“无字段、无配置、无文件、无系统凭证库记录、无 IPC、无响应字段、无日志”，不仅是在界面上隐藏。
- 公司的模型、博查搜索和付费数据源密钥只允许存在公司服务器的密钥管理层，不进入客户端、安装包、前端代码、项目文件和日志。
- 密钥只由独立模型/搜索网关的服务器进程解析。spring-app 业务代码只向内网网关提交能力请求，不读取、不缓存、不转发上游密钥。
- 管理员密钥配置必须是只写操作：提交后任何管理页面和 API 都不能读回完整密钥或密钥片段，只能返回“已配置/未配置”和更新时间。
- BRAIN 客户端只使用本平台的短期登录凭证，该凭证不能直接调用任何上游供应商。
- 所有 AI 和付费联网请求统一经过公司 AI 网关，由网关完成鉴权、套餐、限流、费用上限、模型路由、降级和审计。
- 管理员只在服务端配置“快速、深度推理、代码、文档”等能力路由，普通用户零配置，切换供应商不需要更新客户端。

#### 用户私有模型/BYOK

- 用户可在 BRAIN 设置中添加私有模型，配置供应商类型、模型名称、本地或远程 Endpoint 和自己购买的 API Key。
- 用户 API Key 在保存时由桌面宿主直接写入操作系统安全凭证库；Vue 渲染层提交后立即丢弃原值，不写入 SQLite、项目、`.env`、日志或云端。
- 设置页只能显示“已配置/未配置”、更新时间和“替换/删除”，不允许读回、回填、复制或导出密钥。
- 只有签名的本地 `PrivateModelConnector` 受信任进程能在发起请求的瞬间从安全凭证库取得该密钥并构造 Authorization 头；渲染层、模型上下文、Skill、插件、MCP、Rust Core 和普通 IPC 均不能获取。
- 私有模型请求默认由用户设备直连其 Endpoint，不经过公司 AI 网关，不占用公司模型额度，其费用和数据条款由用户与私有供应商承担。
- 如果用户要求“BRAIN 任何进程都不接触 Key”，则使用“外部本地代理”模式：密钥由用户在自建代理中管理，BRAIN 只保存本地 Endpoint，不配置 Key。

### 5.2 低成本数据策略

- 项目、完整对话、草稿、附件、产物、本地 Skill 和缓存默认只存在用户设备。
- 公司服务端第一阶段不提供项目云盘、自动备份或跨设备同步，不持久化用户提示词和模型回复正文。
- 服务端只保存账号、套餐、权限、设备、管理员策略和计量记录；计量记录仅含请求 ID、能力路由、Token 数、成本、耗时、状态码和时间。
- 用户换机通过手动导出/导入 BRAIN 项目包迁移；云备份仅作为未来付费增值能力。
- 搜索正文、历史行情和预览文件仅在本地按期缓存，不进入服务端永久备份。

## 6. 文档标记与对话修改

### 6.1 文档读取是前置能力

BRAIN 对文档的支持不能只是“生成一个文件”。每种格式都必须完成以下输入链路：

```text
选择/拖入文件
  → 扩展名、MIME 与格式签名校验
  → 本地安全解析
  → 提取文字、结构、页面/幻灯片/工作表与媒体对象
  → 生成分页或分块预览
  → 建立可追溯的结构锚点
  → 用户选中内容后再将有界限的片段交给 BRAIN
```

文档默认在用户设备上读取和解析，不因导入而自动上传公司服务器。只在用户发起 AI 任务时，将本次任务所需的受限文本片段或用户明确选定的内容作为 `TRANSIT_ONLY` 上下文发往公司 AI 网关。

### 6.2 各格式读取、锚定与输出能力

| 格式 | 必须读取的内容 | 结构锚点 | 修改/输出 |
|---|---|---|---|
| 图片 | 尺寸、方向、色彩信息、图像内容；按需 OCR | 图片坐标、选区、缩放基准和 OCR 文本框 | 新图片版本、标注层或导出图片 |
| PDF | 页数、可选文本、图片、页面尺寸、目录；扫描页按需 OCR | 页码、矩形坐标、选中文字和 OCR 坐标 | 批注、页面级修改或导出新 PDF |
| DOCX | 标题、段落、run、列表、表格、页眉页脚、图片和样式 | 段落 ID、文本范围、表格/单元格、图片对象 | 保留样式的新 DOCX 版本 |
| PPTX | 幻灯片顺序、文本、形状、图片、表格、备注和层级 | 幻灯片 ID、形状 ID、文本范围和层级 | 保留版式的新 PPTX 版本 |
| XLSX | 工作表、单元格值/类型、公式、合并区域、表格和图表 | 工作表 ID、单元格/区域、公式和图表对象 | 保留公式与结构的新 XLSX 版本 |
| TXT/Markdown | 编码、全文、标题、列表、代码块和链接 | 行号、字符范围和结构块 | 新文本版本，保留原编码或明确转为 UTF-8 |

“能预览”不等于“能读取”。BRAIN 只有在能返回结构化提取结果、来源位置和解析状态时，才能声称支持该格式。

### 6.3 用户交互

文档创作工作台提供：

- 画笔圈选
- 矩形框选
- 文字高亮
- 下划线和箭头
- 批注气泡
- 橡皮擦和多选标记

标记后生成可插入对话的引用，例如 `第 3 页 · 标记 1`。用户通过对话描述修改要求，BRAIN 返回逐项修改结果，提供查看修改、逐项接受、全部接受和撤销。

### 6.4 统一标记模型

标记不能只保存屏幕坐标，必须同时保存上表定义的结构锚点。标记、对话引用和修改任务都必须指向明确的 `file_id + file_version + structural_anchor`。

原文件始终只读。修改必须创建新版本，并在独立解析、重新渲染和格式验证通过后才允许替换当前版本。

### 6.5 读取失败不得静默

损坏、加密、带密码、过大、扩展名伪装、不支持编码或解析超时的文件，必须进入明确的 `UNSUPPORTED/CORRUPT/ENCRYPTED/TOO_LARGE/TIMED_OUT` 状态。页面不得显示“已读取”，模型也不得根据文件名猜测内容。

## 7. 技术架构

### 7.1 总体结构

```text
BRAIN 桌面客户端
├─ Vue 界面
├─ 本地 SQLite：项目、对话、消息、任务、索引
├─ 本地文件目录：附件、产物、版本、缓存
└─ Rust Core：本地安全执行、文件处理、资源限制
       │ HTTPS + BRAIN 短期登录凭证
       ▼
Java 21 / Spring 公司服务控制面（不读取上游密钥）
├─ 用户、设备、套餐、权限
├─ 管理员模型/搜索/工作台策略
├─ 限流、额度、计量与成本保护
└─ 使用内网服务身份调用独立网关
       │
       ▼
独立 AI/Search Gateway 信任域
├─ 服务器密钥管理层（唯一可解析密钥的位置）
├─ 模型供应商 Adapter
├─ 搜索供应商 Adapter
└─ 受控行情/付费数据源 Adapter
```

本地数据面与公司服务控制面必须分离。服务端在正常请求中可以短暂转发当前上下文，但不将其写入 MySQL、对象存储或业务日志。

### 7.2 Rust 的边界：只开发 BRAIN 桌面端

现有 Java/Spring 是公司远程服务端，继续承担模型路由、供应商适配、鉴权、额度和管理配置。Rust 计划不修改、重写或嵌入 spring-app 后端。

Rust 作为能力层逐步引入，而不是替换全部 BRAIN：

- BRAIN Vue 继续负责桌面界面。
- BRAIN 桌面宿主（Electron main/agentd）负责本地生命周期、IPC、审批和调度 Rust Core。
- Rust Core 负责 BRAIN 本地安全执行、高性能计算和资源敏感型任务。
- Java/Spring 只负责公司远程服务控制面和模型编排，不启动、不调用、不守护 Rust Core。
- Python 行情/科学计算服务按现有节点部署，不与 Rust Core 混成 Spring 进程。

### 7.3 Rust 核心职责

Rust Core 是随 BRAIN 桌面端打包的本地 sidecar 独立进程，不属于 Spring JVM，也不部署到 spring-app 服务器。其职责包括：

- 受限文件读写
- 子进程和终端执行
- Git 操作
- 本地文件索引与增量哈希
- CPU、内存和执行时间限制
- 权限审批令牌校验
- 任务取消和崩溃恢复
- 大规模指标计算和量化回测热点
- 音视频处理任务编排
- 文档渲染 Worker 的进程隔离

Rust Core 只与 BRAIN 桌面宿主通过本地版本化协议通信。第一阶段使用 `stdin/stdout + JSON Lines`，后续如确有并发和性能需求，再评估本地 named pipe/Unix domain socket 或 gRPC。Spring 服务端不在这条通信链上。协议必须包含：

- `protocol_version`
- `request_id`
- `project_id`
- `workspace_type`
- `operation`
- `approval_token`
- `resource_limits`
- `status`
- `error_code`
- `artifacts`

Rust Core 只访问当前用户明确授权的本地项目边界，不接收、保存或转发任何模型/搜索密钥，不访问公司 MySQL，不决定计费和模型路由。AI 返回工具调用建议时，由 BRAIN 桌面宿主校验、请求用户审批，再在本地调用 Rust Core。

## 8. 核心数据模型与存储边界

### 8.1 桌面本地 SQLite 与项目目录

最低需要以下实体：

- `brain_workspace`：工作台定义、能力和启停状态。
- `brain_project`：项目名称、主工作台、所有者和最近状态。
- `brain_project_workspace`：项目启用的辅助工作台。
- `brain_conversation`：项目内对话和当前工作台快照。
- `brain_file`：文件版本、格式、哈希、存储位置和解析状态。
- `brain_artifact`：生成产物、来源任务和验证状态。
- `brain_task`：异步任务、进度、资源限制、重试和错误码。
- `brain_annotation`：标记类型、坐标、结构锚点和引用文本。
- `brain_change_set`：AI 提议的修改、差异、接受状态和回滚版本。
- `brain_skill`：工作台全局或项目局部 Skill。
- `brain_audit_event`：工具调用、审批、文件修改和工作台切换审计。

发布的工作台全局 Skill 与项目局部 Skill 必须分离，项目 Skill 不能自动污染其他项目。

大文件不写入 SQLite BLOB；SQLite 只保存相对路径、大小、哈希、版本和状态。原始文件只保留一份，缓存、日志和中间产物按保留期自动清理。

### 8.2 公司服务端 MySQL

只保存：

- 用户、设备、会话凭证、套餐与权限。
- 工作台、模型能力、联网搜索和降级策略。
- 请求计量、成本、限流、审计状态和脱敏错误。

不建立服务端 `brain_project`、`brain_message`、`brain_file` 正文镜像，不保存用户项目文件。

登录 Access Token 仅保留在客户端内存中；如需“保持登录”，只把 BRAIN Refresh Token 保存到 Windows Credential Manager、macOS Keychain 或 Linux Secret Service。这是 BRAIN 身份凭证，不是上游模型密钥，并且必须可由服务端撤销。

## 9. 稳定性与安全边界

- 文档转换、OCR、回测和媒体处理不得运行在 Spring 请求线程。
- 大文件分页、按需渲染，不一次加载完整文档。
- Worker 使用任务队列、超时、内存限制、CPU 限制和熔断。
- 文件先验证格式签名，再解析；损坏、加密和超限文件明确失败。
- Office 宏永不执行。
- 每次修改生成新文件，完成后原子提交，失败不覆盖旧版本。
- 工具调用使用最小权限和一次性审批令牌。
- Rust Core、文档 Worker、媒体 Worker 崩溃不能带崩 BRAIN 桌面宿主，更不影响公司 Spring 服务端。
- 所有外部服务设置连接、首包、总时长超时和有限重试。
- 任务、文件和对话都必须支持重启恢复和幂等执行。

## 10. 阶段实施计划

### 阶段 0：产品合同与工程基线

目标：先固定数据、交互和协议，避免七个工作台各自重复建设。

实施：

1. 固化工作台、项目、对话、文件、产物、任务、Skill 的归属模型。
2. 固化左上工作台切换、左侧项目/对话、右侧工具的界面合同。
3. 固化本地 SQLite/项目目录与服务端 MySQL 的数据边界，建立“正文不上云”合同测试。
4. 建立统一图标、状态、错误码、加载、空态和失败态规范。
5. 分别定义“BRAIN 客户端 ↔ Spring AI 网关”远程协议与“BRAIN 桌面宿主 ↔ Rust Core”本地协议，两者不得混用。
6. 建立功能开关，未完成模块可逐项启用，不发布空白页。
7. 建立“客户端绝无公司密钥、用户私有密钥只进安全凭证代理、服务端不记录正文”安全基线。

验收：七个工作台的字段、状态迁移、权限、错误码和接口契约通过评审，并有自动化合同测试。

### 阶段 1：七工作台骨架

目标：七个入口全部可用，完成通用闭环。

实施：

1. 实现左上工作台选择面板和自动路由建议。
2. 切换工作台时筛选项目、恢复项目上次对话、加载右侧专业导航。
3. 七个工作台均支持创建项目、新对话、上传文件、查看产物和任务。
4. 保留输入草稿和当前对话，提供最近项目跨工作台返回。
5. 管理端提供工作台启停、能力开关和默认模型配置。

验收：七个工作台均能完成“创建项目—上传文件—发起对话—生成产物—查看任务—重启恢复”。

### 阶段 2：量化交易专业闭环

目标：首先交付可真实使用的专业工作台。

实施：

1. 接入 AKShare 历史行情和免费新闻源。
2. 支持日、周、月线，前复权、后复权、不复权和指定日期区间。
3. 展示 OHLC、成交量、成交额、涨跌幅和 K 线。
4. 完成模拟买卖、持仓、盈亏、资金曲线和交易记录。
5. 完成 Skill 策略创建、回测、收益比较和雷达定时触达。
6. 时效问题接入搜索网关，强制来源和时间标注。

验收：真实行情能够渲染；模拟交易账目一致；同一回测重复执行结果可复现；搜索失败不编造。

### 阶段 3：数据与决策、软件与自动化基础能力

目标：复用数据和任务底座，支撑后续工作台。

实施：

1. 数据与决策支持 CSV/XLSX 导入、表格预览、统计和图表。
2. 软件与自动化支持项目文件、代码查看、受控命令和任务日志。
3. 建立 Flow 基础节点、条件分支、人工审批、定时和失败重试。
4. 工具调用全部经过权限边界和审计。

验收：数据文件可查询并生成图表；受控任务可取消、重试、重启恢复；越权工具调用被拒绝并记录。

### 阶段 4：文档创作与可定位标记

目标：先交付“导入—读取—预览—引用”，再交付“圈选内容—对话修改—对比确认”。

实施：

1. 实现六类格式的安全导入、真实读取、结构化提取和可见解析状态。
2. 先完成图片、TXT/Markdown 和普通 PDF 的分页/分块预览与标记。
3. 通过独立 Worker 增加 DOCX、PPTX、XLSX 读取和渲染，扫描 PDF 通过 OCR 建立坐标和文本锚点。
4. 建立统一 annotation 和 change set 模型。
5. 增加修改前后对比、逐项接受、全部接受、撤销和版本恢复。

验收：每种格式都能读出测试文件中的指定文本、表格/对象和页/幻灯片/工作表数；缩放和重启后标记仍指向正确位置；原文件不被覆盖；生成文件能被不同实现的独立解析器读取并重新渲染。

### 阶段 5：Rust Core 最小可用版本

目标：为 BRAIN 桌面端建立安全本地执行和高性能能力底座，spring-app 后端不做 Rust 改造。

实施：

1. 创建独立 Rust workspace、协议 crate、执行器 crate 和 CLI/service 入口。
2. 首批实现文件读取、目录枚举、哈希、受控命令、取消和超时。
3. BRAIN 桌面宿主通过版本化本地协议调用 Rust Core，并校验审批令牌。
4. 建立路径白名单、资源限制、结构化日志和崩溃自动拉起。
5. 加入跨平台构建、签名、校验和回滚机制。

验收：Rust Core 被强制终止时 BRAIN 主服务继续运行；越界路径和过期审批被拒绝；任务取消在规定时间内生效。

### 阶段 6：视频制作

目标：完成脚本到可预览视频项目的最小闭环。

实施：素材管理、脚本、分镜、字幕、配音、预览和异步导出；媒体处理放入隔离 Worker，Rust 负责进程与资源控制。

验收：长任务不阻塞对话；失败可重试；导出产物可播放且音画时长一致。

### 阶段 7：音乐创作

目标：完成歌词/提示到可试听音频项目的最小闭环。

实施：歌词、风格、速度、试听、音频版本和导出；后续增加 MIDI、多音轨、混音和母带。

验收：音频可播放、波形和时长正确；版本可恢复；模型失败不产生伪成功产物。

### 阶段 8：游戏制作

目标：统一策划、资产、代码和可运行原型。

实施：项目结构、策划、世界观、角色、关卡和资产管理；调用文档、图像、音乐、视频和软件工作台能力；后续增加战斗、动画和自动测试。

验收：跨工作台产物保留来源；游戏项目可打包最小原型；资产版本和依赖关系可追踪。

### 阶段 9：生产强化与规模化

目标：在用户增长前完成稳定性、成本和安全治理。

实施：

1. 全链路指标、追踪、结构化日志和错误聚合。
2. 模型、搜索、文档、媒体和 Rust 任务的成本配额。
3. 压力测试、故障注入、备份恢复、灰度发布和一键回滚。
4. 插件与 Skill 权限审查、签名和来源治理。
5. 根据监控数据决定是否将回测热点、索引或媒体任务进一步迁移到 Rust。

验收：达到既定并发与恢复目标；故障不跨 Worker 扩散；成本超限自动降级或停止；回滚演练成功。

## 11. 推荐执行顺序

实际开发按以下顺序推进：

```text
阶段 0 工程基线
  → 阶段 1 七工作台骨架
  → 阶段 2 量化交易闭环
  → 阶段 3 数据、软件与自动化底座
  → 阶段 4 文档标记修改
  → 阶段 5 Rust Core
  → 阶段 6 视频制作
  → 阶段 7 音乐创作
  → 阶段 8 游戏制作
  → 阶段 9 生产强化
```

阶段 5 的协议应在阶段 0 定义，Rust 代码在业务边界稳定后开发，避免过早重写和双线返工。视频、音乐和游戏可在阶段 1 先提供项目、文件和 BRAIN 对话，专业编辑器分别在后续阶段解锁。
