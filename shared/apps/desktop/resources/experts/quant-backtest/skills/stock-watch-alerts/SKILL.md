# 长期关注与参考提醒

将用户的关注对象和规则存入持久数据库，不能把聊天历史当作长期记忆。使用本目录 `scripts/watch.py`；完整命令和服务配置见 [运行说明](references/operations.md)。脚本需要 Python 3.9+，仅使用标准库。

需要可点击的本地管理页面时，运行 `scripts/web.py --db <私有路径> --user <本地用户>`；用 `--prototype <用户提供的 HTML>` 可在原型增加“长期关注”页签。它与 CLI 共用数据库及规则引擎，不读取原型假行情；未带 `--deliver` 时绝不外发。仅绑定 127.0.0.1，不能作为公网多用户服务。

## 明确边界

- 只提供用户规则触发的观察/买入参考/卖出参考；不推断“必涨”“最佳时机”或获利保证。
- 不调用 `quant.strategy.run`、`quant.portfolio.*`、模拟交易、券商或其他下单接口。提醒服务没有订单执行能力。
- 不把用户之前为其他用途提供的邮箱、手机号或密码当作本监控服务的通知授权。确认收件地址、渠道、关注对象、规则和频率后才启用投递。
- 邮件/短信包含标的、规则、观察价格、数据时间、来源、事件编号及“仅供参考，不执行交易”；保留触发证据。
- 新建关注或修改规则后，首次有效行情只建立基线，不发送已有历史信号。此后条件从不成立变为成立才提示。同一根行情不会重复生成事件。
- 行情失败、缺字段、价格无效、时间戳无时区/超前、数据过期时，记录监控错误，不制造信号，也不发送该订阅积压提醒。

## 工作流程

1. 用稳定的本地用户 ID 和其专属数据库路径，先 `list`/`status` 读取已有关注。脚本的用户分区不是远程身份认证，不可直接作为多用户公网 API。
2. 将公司名解析为用户确认的交易所/标的代码；不猜代码。行情不支持的资产要明确说明。
3. 询问并保存长期偏好、监控频率和明确规则。可用 `price_below`、`price_above`、`ma_cross_up`、`ma_cross_down`；用户为每条规则选择 `buy_reference`、`sell_reference` 或 `observe`。没有确认阈值时仅保存为暂停，不替用户选择买卖点。
4. `profile` 保存邮件/短信接收方式与明确的渠道启用状态，`subscribe` 保存标的、说明及规则。修改前向用户说明修改对象；暂停/退订会取消待发消息。
5. 先 `check` 验证配置，再执行 `poll`，用 `status` 和 `alerts` 检查行情来源、时间、监控错误与队列；此阶段不外发。明确告知首次仅建立基线。
6. 在已授权发送且服务已配置时运行 `run --deliver`，每轮监控后处理通知队列。只说“监控已启动”当后台进程实际运行；要持续运行须机器在线且进程存活。进程关闭会停止监控，重启后恢复订阅。默认不注册系统任务、不启动任何真实订阅。
7. 使用 `pause`、`resume`、`unsubscribe` 管理订阅；`profile --disable-email/--disable-sms` 撤销渠道。让用户知道数据库位置和停止方式。

## 与已有技能配合

需要研究公司基本面时可参考 `equity-research-workflow`，需要验证策略时可参考 `quant-backtest-workflow`。它们只辅助解释，不替代真实行情或本脚本规则。当前监控是行情条件触发，不包含自动抓取新闻/公告、自然语言预测或完整回测；明确区分当前能力和待接入能力。

## 完成判断

关注记录可在重启后读取；真实行情连接状态可查；触发和未触发均可解释；重复轮询不重复提醒；暂停/退订后不再投递；邮件/短信真实送达只能由服务回执或收件人验证，不能把 dry-run、SMTP 接收或网关受理说成用户已收到。
